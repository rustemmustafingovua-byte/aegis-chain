# Сеть: несколько узлов, догон и форки (v1.16)

До v1.16 devnet был «сетью из одного процесса»: второй узел, отставший хотя бы на
один блок, получал `bad height`, отправитель получал штраф, и узел застревал
навсегда. Теперь сеть можно поднять по-настоящему — и она сходится.

## Что изменилось

| Было | Стало |
|---|---|
| `new_block` с height > head+1 → штраф −20 и отказ | классификация → `sync_request` без штрафа |
| указатель слота двигал только избранный пропозер → мультиватор разъезжается | слот = `(now − GENESIS_TIMESTAMP) / SLOT_MS`, одинаков у всех |
| одинаковый ключ у всех узлов → форки на каждом слоте | ключ из `AEGIS_VALIDATOR_SEED`, общий генезис-конфиг |
| дубликаты блоков ретранслировались | дубликаты / форки игнорируются, ретрансляция только принятых |
| наблюдать состояние сети нечем | `aeg_syncStatus`, метрики `aeg_peer_count`, `aeg_forks_seen` |
| изолированный узел продолжал «майнить» свою ветку | без живого кворума ≥2/3 стейка блок не производится |
| checkpoint каждого узла подписан только им (33%) | узлы ко-подписывают checkpoint друг друга → 2/3+ |

## Классификация входящего блока — `core-ts/sync.ts`

```
classifyBlock(chain, block) → next | duplicate | gap | fork

next       height == head+1 && prevHash == head.hash   → accept + relay
duplicate  уже есть / прунено                          → ignore, без штрафа
gap        height > head+1                             → sync_request, без штрафа
fork       конфликт с известной высотой                → ignore + счётчик, без бана
```

Форк — не обязательно атака: два честных пропозера в одном слоте дают ровно
такой же симптом. Поэтому форк **наблюдается** (`forksSeen`, warn в лог), а не
наказывается баном. Наказываются только блоки, не прошедшие проверку
(`reject`: подпись, merkle root, хеш, пропозер).

## SyncTracker: не спамить и не спать

`SyncTracker` держит на пира `cooldown` (3 с) и экспоненциальный backoff от числа
неудач (до 60 с), плюс отсечку после 6 неудач подряд. Запрос повторяется, когда
цель выросла (новая высота), но не чаще базового cooldown'а.

```
new_block(h=42) при head=37
  → gap → sync_request(fromHeight=37)   (1 раз)
  → sync_response(37..42)               → noteSuccess, height=42
  → если пир всё ещё впереди            → ещё один запрос после cooldown
```

`sync_response` применяется строго по порядку; блок не на своём месте →
`noteFailure` + маленький штраф, узел не застревает на «дырявом» ответе.

## Генезис для нескольких валидаторов

`AEGIS_GENESIS_VALIDATORS` — путь к JSON или inline JSON:

```json
{ "validators": [
  { "edPublic": "<base64>", "mlPublicKeyB64": "<base64>", "stake": "10000000000",
    "address": "aeg1…", "balance": "100000000000", "humanityScore": 90 }
] }
```

`core-ts/genesis.ts` применяет список **отсортированным по `edPublic`**, поэтому
два узла с одним файлом получают одинаковый ledger и одинаковый `stateRoot`.
На восстановлении цепи балансы не начисляются повторно — только досоздаются
отсутствующие записи (идемпотентно).

Узел, чьего ключа нет в списке, работает **наблюдателем**: RPC и синк есть,
блоки он не производит (иначе гарантированный форк).

## Переменные окружения

| Переменная | Смысл |
|---|---|
| `AEGIS_VALIDATOR_SEED` | ключ узла: 64+ hex или любая строка (→ sha256, 32 байта) |
| `AEGIS_GENESIS_VALIDATORS` | общий список валидаторов (путь или JSON) |
| `AEGIS_STATE_FILE` | свой файл состояния на узел |
| `AEGIS_P2P_PORT` | TCP-порт gossip (по умолчанию port−5000) |
| `AEGIS_LIBP2P_PORT` | libp2p/Noise порт (по умолчанию p2p+1000) |
| `AEGIS_BOOTSTRAP` | `host:port,host:port` — к кому подключаться на старте |
| `AEGIS_LIBP2P_PEERS` | multiaddr-список для libp2p bootstrap |
| `AEGIS_EMPTY_BLOCK_SLOTS` | heartbeat: пустой блок каждые N слотов |
| `AEGIS_CHECKPOINT_EVERY` | подписанный checkpoint каждые N блоков |

## Запуск сети из трёх узлов

```bash
npm run devnet:multi            # 3 узла: :8901-:8903, Ctrl+C останавливает все
CHECK_HEIGHT=6 npx tsx scripts/devnet-multi.ts --check   # поднять, проверить, выйти
```

Скрипт сам создаёт `~/.local/state/aegis-devnet/genesis.json` из трёх
детерминированных ключей, поднимает узлы с разными state-файлами и
`AEGIS_BOOTSTRAP`, ждёт, пока все три совпадут по height/head/stateRoot, и
печатает распределение пропозеров.

Проверенный результат (v1.16):

```
final state:
  :8901 height=6 head=28b4e8cfded960a9… root=856a4b87f8a5f790…
  :8902 height=6 head=28b4e8cfded960a9… root=856a4b87f8a5f790…
  :8903 height=6 head=28b4e8cfded960a9… root=856a4b87f8a5f790…
block proposers: {"GcY0Q4YfRx":2,"HoTDhgTijz":2,"YYVw38l6Ez":2}
```

## Кворум: не производить блок в изоляции

Узел без реорганизации не должен создавать ветку, которую потом нельзя склеить.
Перед пропозингом считается **видимый стейк**:

```
visible = {свой ключ} ∪ {edPublic пиров из HELLO (подписанного)}
connectedStake * 3 >= totalStake * 2      → можно предлагать блок
```

Если кворума нет, слот пропускается (`proposal skipped: no quorum`,
раз в 10 тиков в лог). Изолированный узел перестаёт расти и просто ждёт
переподключения — цепочка остаётся одной.

Порог считается как точные 2/3 (`*3 >= *2`), а не как 6667 bps: в звезде
каждый лист видит только bootstrap-узел, и округление 6666.67→6667 потребовало бы
3-из-3, то есть запретило бы производство блоков вообще.

## Bootstrap-переподключение

`addBootstrap(host, port)` запоминает пира и каждые 5 с проверяет, жива ли связь;
если сокет закрыт — дозванивается снова. Раньше одиночный `connect()` мог
попасть в момент, когда сосед ещё не слушает (`ECONNREFUSED` проглатывался),
и узел молча оставался один — именно так возникали «две истории» на devnet.

## Checkpoint-кворум в мультиваторе

Каждый узел после создания checkpoint'а рассылает его соседям
(`AEGIS_CHECKPOINT_PEERS=http://host:port,...`, RPC `aeg_checkpointOffer`).
Сосед подписывает **только свой tip**: `height/blockHash/stateRoot/nullifierRoot`
обязаны совпасть с его состоянием, иначе `signed:false` с причиной. Подпись —
это аттестация проверенного состояния, а не услуга «подпиши что дали».

Ответы сливаются в локальный store (одинаковый timestamp = одно и то же
сообщение), повторы с backoff'ом на случай, если сосед ещё не применил блок.
Проверено на живом devnet: `checkpoint h=4: signatures=2, signed 6667 bps, ok=true`.

## Наблюдаемость

`aeg_syncStatus` → `{ height, head, tcp: { peers, forksSeen, sync[] }, libp2p: … }`,
где `sync[]` — `peerId, height, attempts, failures, lastSyncAt, lastError`.

Метрики Prometheus (`/metrics`): `aeg_peer_count`, `aeg_forks_seen`,
`aeg_height`, `aeg_mempool`.

## Границы (честно)

- **Нет реорганизации**: узел не переключается на более длинную ветку. Форк
  виден в `forksSeen`, но разрешается социально (перезапуск с общего snapshot)
  или будущим fork-choice. Для devnet этого достаточно, для mainnet — нет.
- **Нет заголовочного синка в p2p**: догон идёт блоками (до 100 за ответ).
  Для длинного отставания это дороже, чем headers-first (см. v1.4 roadmap).
- **Gossipsub без подписи**: идентичность узла подтверждается HELLO-подписью и
  подписью блоков, а не ключом libp2p (`StrictNoSign`). Сообщения, не прошедшие
  проверку блока/транзакции, штрафуются.
- **Checkpoint-кворум** собирается через RPC между узлами, а не через p2p-gossip:
  нужен `AEGIS_CHECKPOINT_PEERS` со списком адресов. Узел подписывает только
  checkpoint на своём tip — если сосед отстал, подпись придёт позже (retry),
  а не будет выдана «на веру».
