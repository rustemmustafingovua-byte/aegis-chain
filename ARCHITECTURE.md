# AEGIS — Архитектура

[Назад к README](README.md)

## 1. Модель угроз (Threat Model)

### 1.1. Классический хакер
- Фишинг: fake front-end, подмена адреса в буфере обмена, Drainer-бот.
- Вредонос: стилер сидов, кейлоггер, подмена подписи.
- Сеть: MITM, eclipse, Sybil-валидаторы.
- «Harvest Now, Decrypt Later»: сбор шифртекстов для будущих квантовых машин.

### 1.2. ИИ-агент (новый класс)
| Атака | Пример | Почему ммёт обычную крипту |
|---|---|---|
| **Prompt-injection draining** | Агент решает: «отправь всё на адрес X», пряча это в текст PDF/сайта | Агент кликает «подписать» без понимания намерения |
| **Scale social-engineering** | 1M персонализированных фишинговых сообщений | Человек не отличит, частота убийственна |
| **Autonomous 0-day** | Агент сам пишет эксплойт к кошельку в 03:00 | Нет человека, который бы усомнился |
| **Timing / behavioral fingerprint** | Агент действует каждые 500ms ровно, без «шума» | Легко автоматизировать перебор |
| **Deanonymization-by-clustering** | Агент связывает адреса по временным паттернам | Анонимность умирает по метаданным |
| **Colluding agents** | 10k агентов-голосуют за злонамеренный апдейт | Sybil + governance захватывается |

### 1.3. Цели
- **CIA:** конфиденциальность (PQ + metadata resistance), целостность (intent-binding), доступность (threshold — нет одной точки отказа).
- **Agent-Resistance:** агент не может подтвердить «я — живой человек с реальным намерением именно этой операции».

## 2. Рубеж 1 — PQ-криптография (Hybrid-First)

Каждый ключ — **гибрид**:
```
PublicKey = { Ed25519_key, ML-DSA_key (Dilithium3), XMSS_one_time }
Signature = Ed25519(sig)  +  ML-DSA(sig)  +  H( prev_sig || local_entropy )
```

- **Ed25519** — быстрый, совместимый с существующими кошельками.
- **ML-DSA / Lattice** — устойчив к Шору, стандарт NIST FIPS 204.
- **XMSS / H** — hash-based одноразовость: даже если решетки рухнут, хешовое время остаётся.

Зачем гибрид, а не «только PQ»? Так мы не теряем совместимость и не ставим всё на один молодой стандарт. При компрометации одного примитива — второй держит.

> Квантовый атакующий должен сломать *оба*, чтобы подделать подпись. 

Дополнительно:
- **Адреса вращающиеся:** адрес = H(pubkey || ephemeral_nonce || chain_id). Old-адреса сжигаются после траты (Forward Secrecy). «Собрать сейчас — расшифровать потом» не работает: эфемерный nonce утирается.
- **Без адресов-ловушек:** canary-адреса с внятной меткой «AEGIS_CANARY», любой drains на них — сканируется, атакующий разоблачается.

## 3. Рубеж 2 — Порбог и аппаратный якорь

### 3.1. Shamir Secret Sharing 3-из-5
Сид разбивается на 5 шар: телефон, аппаратный ключ, бумажный бэкап, доверенное лицо, серверный HSM.
- Потерять 2 шара — не беда. Украсть 2 шара — не достаточно. Нужны 3.
- Реконструкция происходит **только в эфемерной сессии** (ключ живёт 60 секунд, потом стирается из RAM).
- Вредонос на одном устройстве видит только 1 шар.

### 3.2. Hardware Anchor + Passkey
- Подписи делаются только через Passkey/FIDO2 или локальный secure enclave (Apple Secure Enclave / Android Keystore / TPM).
- Ключ **неизвлекаем** из железа. Агент, работающий в браузере, не может выгрузить приватный ключ.
- **Эфемерные session-ключи:** браузер запрашивает 60-секундный, одноразовый, ограниченный по сумме ключ. Утек — ущерб ограничен, ключ сам умрёт.

## 4. Рубеж 3 — Anti-AI Shield ⭐ сердце AEGIS

### 4.1. Intent Binding (связывание намерения)
Обычная подпись: «подписываю байты `0xdead...`». Пользователь не знает, что внутри.

AEGIS-подпись:
```
Tx = {
  to: "lmn1...",
  amount: 10,
  intent: "продажа велосипеда Алексею, сделка #4721",
  domain: "marketplace.aegis.example",
  expiry: 120s,
  human_context_hash: H(entropy_device || prev_tx_hash || time_window)
}
Signature = Sign( H( canonical(Tx) ) )
```

- **Структурное намерение на человеческом языке + машиночитаемое.** Пользователь видит *зачем*, кошелёк проверяет, что поля совпадают.
- Сайт не может подсунуть `to=attacker` под видом «оплаты 10 USDC за стул»: железо покажет **полный рендер** (адрес, сумма, intent, домен) на экране блокировки.
- Агент не может молча подменить получателя: intent-хеш сломается, подпись не сойдётся.
- **Domain binding:** подпись по умолчанию привязана к домену. Копипаст подписи на другой сайт — невалиден.

### 4.2. Proof-of-Liveness (не «я человек», а «я живой *прямо сейчас*»)
Чтобы сделать большую/рискованную операцию, нужно свежее доказательство:
```
Challenge = H( last_block_hash || time_window(±30s) )
Response  = Sign( Challenge || local_entropy )
local_entropy = H( sensor_noise || secure_RNG || typed_cadence_hash )
```

- `local_entropy` **невозможно сгенерировать без реального железа и реального человека**: ему нужны шум сенсоров, каденс печати, микросекундный тайминг.
- Агенты действуют слишком ровно/быстро — их распределения палят скоринг (см. 4.3).
- Челендж живёт 30 секунд. «Собери подпись заранее» — не работает.

### 4.3. Behavioral Scoring (скоринг поведения)

Каждый шаг человека даёт эвристику:
- распределение интервалов между кликами/печатанием (энтропия),
- время между «увидел сумму» и «подтвердил» (слишком быстро = бот),
- количество отмен/редактирований (человек сомневается, агент — нет),
- уникальность NUllifier: каждая сессия имеет fresh «human_context_hash».

```
human_score = 0..100
if score < 70: _tx_queued for guardian review
if score < 40:  tx_blocked
```

Агент **может** имитировать, но имитация дорога: нужно держать человеческую энтропию, время реакции, приватное железо. Нам не нужна идеальная защита — нам нужна **экономика**, где атака дороже выгоды.

### 4.4. Rate-Limits по Proof-of-Humanity, а не по IP
- IP можно менять. «Живого человека при этом железе» — нет.
- Each `human_context_hash` может сделать ≤ N операций / час. Перебор ключей упирается в стену: атакующий без новых живых герметично-закрытых удостоверений не «брутнет» сеть.
- **Time-lock + Veto:** операции > порога уходят в 60-секундное окно, где любой из 3 «хранителей» (guardians) может наложить вето hardware-действием. Агент украл сессию — у человека есть 60 секунд спасти деньги.

### 4.5. Semantic Firewall (стена от prompt-injection)
- Любой текст из веба / PDF / чата **никогда не получает права подписи**. Все входящие тексты рендерятся как `untrusted_text`, отделены от `signed_intent`.
- Кошелёк показывает предупреждение: «Этот текст требует подписи. Допускаете?» — триггерится **только** по аппаратному ключу, не по клику агента.
- Это «два канала»: агент — тексты, человек — железо. Разрушьте один — другой не даст увести деньги.

## 5. Сеть и консенсус

- **PoS с 2/3 финальностью (как в Lumen)**, но валидаторы обязаны подтвердить «AEGIS Hybrid» ключи.
- **Слашинг за colluding agents:** если валидатор голосует подозрительно ровными временными паттернами — slashed.
- **Governance без Sybil:** голоса взвешены по proof-of-humanity + stake, не по количеству кошельков.
- **Memosybil-resistant:** каждая операция платит микро-комиссию в условные единицы «humanity» (не токены, а отслеживаемый лимит). Бот-рой — дорого.

## 6. Честные ограничения

- Biometric / human_score даёт false positives: не все люди печатают «энтропийно». Нужна калибровка и allowlist.
- PQ-ключи больше и медленнее. Хранить +1 подпись (ML-DSA ~2KB) — цена приемлема для кошелька, непредсказуема для массового ончейн-трафика.
- Hardened-UI (внешний экран) нужен для полной защиты от зловреда, который лжёт самому приложению.
- **Защита не снимает роль пользователя:** если человек сам подтверждает фишинг своим железом — протокол не спасёт. Поэтому intent UI — самое важное.

## 8. Почему не «продать как BTC»

AEGIS специально **не гонится за ценой**. Ценность — trust layer. Поэтому:
- премьерный use-case: платежи, где цена «ошибки» высока (партнёрские расчёты, escrow, семейные кошельки, доступ DAO).
- спекуляции во вторичном рынке — ограничение, а не цель.
